改造前的 5 处误读（对应图中红点）

  • ① 绿色「监控中」被读成“GitHub 可用 / 加速已生效”。它只表示“数据源自动测速在跑”，与 GitHub 能否打开无关；同一屏下方可以出现“所有数据源都不可用”。
  • ②③ 最佳响应 / 综合评分没有单位、口径和含义。用户会把 86 ms 当成“网页打开耗时”，把 92.5 当成“速度得分”；两者其实只描述某条镜像线路本身。
  • ④ 数据源 12 个 / 可用 8被读成“12 个 GitHub 入口，8 个能用”。它统计的是本程序配置的镜像源，不代表 github.com 的可达性。
  • ⑤「重新检测」实际执行应用加速（写 Hosts）：按钮文字说检测，命令是 ApplyHosts。“我只是想再看一眼”会变成一次系统写入。
  • 同屏两个「取消」：快捷栏的取消是“中止加速”，列表里的取消是“取消全选”。用户点错会得到完全不同的结果。

改造后的对应关系

  • A 一句话结论 + 一个动作：把“监控中/最佳响应/评分/数据源计数”四个内部指标移出首屏；首屏只留“可用/部分可用/不可用 + 是否已开启加速 + 一个开关按钮”。
  • B 三个口径，一个主指标：整页耗时做主指标（回答“网页快不快”），单次请求与下载速度作为辅助并强制标注口径；评分不再作为首屏指标。
  • C 失败区只有一个原因句 + 一个主动作：403 配额/线路不可达/本机断网分别给不同人话与动作，不再把“线路不可达”说成“网络错误”，也不再出现“重新检测”实际去写 Hosts 的错位。
  • 折叠层：数据源列表、评分、域名明细保留但不抢占主路径；命名统一为“加速线路 / 依赖站点 / 连接耗时”。
  • 导航按问题分组：能不能用 / 我的加速 / 检查与修复 / 下载 / Hosts 与备份 / 设置 / 帮助；原“网络监控”“子域健康检查”“官网访问诊断”合并进“检查与修复”。
