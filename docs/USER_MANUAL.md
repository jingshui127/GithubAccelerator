## 1. 产品简介

### 1.1 产品概述

**GitHub 加速器 Pro** 是一款专为解决中国大陆地区 GitHub 访问问题而设计的桌面应用程序。通过智能管理 Hosts 文件，自动选择最优 IP 地址，实现 GitHub 服务的快速稳定访问。

### 1.2 主要功能

| 功能 | 描述 |
|------|------|
| 🚀 一键加速 | 先拿将要写入的 `github.com` 备选 IP 与当前直连交替对比；未快 20% 时不写入 Hosts 并提示「当前网络换 IP 改善不了」，达标才写入合并后的多域名映射，可随时恢复。非管理员时顺序为「先判、后提权」：判定不通过不会弹 UAC |
| 🩺 检查与修复 | 依赖站点检查、官网诊断、连续采样合并为一页，先给结论再给证据 |
| ↩️ 回到原始状态 | Hosts / Git / 防护版 / 首启快照四类改动一次性逐项还原，执行前列清单确认 |
| 📥 下载与 Git 加速 | 镜像链接转换与 Git 重写，统一收在「加速方式（详情）」 |
| 💾 备份与恢复 | 创建/查看/删除 Hosts 备份，导出/导入应用数据（设置页） |
| 🌙 主题切换 | 深色/浅色主题支持 |

### 1.3 适用场景

- 📦 克隆/拉取 GitHub 仓库
- 🌐 浏览 GitHub 页面
- 📥 下载 Release 文件
- 🔍 搜索代码和项目
- 📝 编辑 Wiki 和 Issues

## 3. 安装指南

### 3.1 下载安装

1. 从 [GitHub Releases](https://github.com/jingshui127/GithubAccelerator/releases) 下载最新版本
2. 运行 `GithubAccelerator.Setup.exe`
3. 按照安装向导完成安装
4. 首次运行时，可能需要以**管理员身份**运行

### 3.2 便携版安装

1. 下载 `GithubAccelerator.Portable.zip`
2. 解压到任意目录
3. 运行 `GithubAccelerator.UI.exe`

### 3.3 卸载

卸载前先清理本项目写入 Hosts 的加速块（只删块内内容，块外内容保持原样）：

- 图形界面：主界面点「停止加速」
- 命令行：`GithubAccelerator.Cli.exe --restore`（需要管理员权限）
- 若该块内容曾被你手动修改，程序会明确提示"块内容与上次写入不一致"，不会静默覆盖块外内容

清理后再卸载：

- **安装版**: 通过"设置 > 应用 > 已安装的应用"卸载
- **便携版**: 直接删除文件夹

> 如果直接删除程序而未清理，加速块会残留在 Hosts 中。GitHub 换 IP 后可能无法访问，
> 此时用任意文本编辑器删除 `# === GitHub Accelerator Start ===` 到
> `# === GitHub Accelerator End ===` 之间的内容即可。

## 4. 快速入门

### 4.1 首次使用

#### 步骤 1: 启动应用

双击桌面图标或开始菜单中的"GitHub 加速器 Pro"启动应用。

#### 步骤 2: 授予权限（按需，判定通过后才提示）

程序不会一启动就请求管理员权限，也不会在门槛判定前弹 UAC。点「开启网页加速」后，先用当前身份做**只读**判定（不需要管理员权限、不写 Hosts）；只有判定通过、确实需要写 Hosts 时，才会弹一次管理员授权。判定不通过时不会出现 UAC 提示。

#### 步骤 3: 等待自动探测

应用启动后会自动探测加速线路并给出结论。主界面第一层「现在能不能用 GitHub？」只回答一个问题：现在到底能不能用、要不要点加速。

#### 步骤 4: 开启加速

1. 点「🚀 开启网页加速」（全应用唯一的主加速入口）
2. 程序先把**即将写入的** `github.com` 备选 IP 与当前直连做交替对比（同页面、同一时间窗）；**备选 IP 没有超过直连 20% 时不写入 Hosts**，并明确提示「当前网络换 IP 改善不了」
3. 判定是分级的：先做 2 组快速初判（通常几秒出结果），明显不达标直接结束；只有初判接近临界或可能达标时，才继续做完整的 6 组对比。备选 IP 连不上（连续 2 次加密连接预检查失败）或整页打开连续超时会提前结束，不会每轮都等满超时。界面会写明当前在做哪一步、预计还要多久，随时可点「取消」——取消后不提权、不写 Hosts
4. 达到门槛才写入合并后的多域名映射；非管理员时，只有判定通过之后才弹一次 UAC 请求写入权限（判定与 UAC 的顺序是"先判、后提权"）。写入后可随时点「↩️ 恢复原始访问」只移除本程序的加速块
5. 主按钮、来源卡片「应用此源」、分组「用此分组加速」、自动切换、自动刷新、CLI 共用同一道判定，不存在绕过门槛的写入口

#### 步骤 5: 验证与回退

打开浏览器访问 [github.com](https://github.com)。想回到原始状态，点「↩️ 恢复原始访问」，或到「Hosts 与备份 → 回到原始状态」一次性还原全部改动。

## 5. 功能详解

### 5.1 仪表盘

仪表盘是应用的主界面，按「能不能用 / 快不快 / 出问题怎么办」三层排列。

#### 5.1.1 第一层：能不能用

只有一个结论和一组自适应动作，不会同时出现两个主按钮，也不在首屏放第二个「能不能用」信号。

| 元素 | 说明 |
|------|------|
| 结论 | 四态直答：`正在检查 GitHub 直连…` / `GitHub 直连可用，无需加速` / `GitHub 直连不通，建议开启加速` / `已开启网页加速` |
| 动作说明 | 一句话写清点完会怎样：先测速比较，比直连快 20% 才写入；不达标不改系统文件、不弹管理员确认 |
| 🚀 开启网页加速 | 未写入加速时显示；含 20% 准入门槛、预览、可撤销、只写 `github.com` |
| ↩️ 恢复原始访问 | 已写入加速时显示；移除本程序的 Hosts 加速块 |
| 中止本次加速 | 仅加速进行中显示 |
| 🩺 检查与修复 | 进入合并后的排查页；首屏不再重复「暂停自动测速」开关 |

#### 5.1.2 第二层：快不快 / 哪里慢

三张卡并排，每张都标出单位、含义、口径与更新方式。

| 卡片 | 指标 | 口径与更新 |
|------|------|-----------|
| 整页打开耗时（页面基本加载完，不执行页面脚本） | 秒 | 直连与备选 IP 交替对比取中间值；手动实测；**只作相对比较，不是绝对真值** |
| 单次请求响应 | ms | 最快线路一次请求到首字节，3 次取中间值；每 10 秒更新 |
| 下载速度 | MB/s | 最多 2 MB / 5 秒窗口，仅测镜像下载；手动测速，未测时显示「未测」不编造数字 |

#### 5.1.3 第三层：出问题怎么办

只在「所有加速线路都不可用」时出现，给出原因与「恢复原始访问（关闭加速）」「打开 github.com 原始链接」「重新开启加速」「关闭」。

#### 5.1.4 详情入口

- **加速方式（详情）**：网页 / Git / 下载三种机制的总说明，默认折叠；
- **📡 我的加速 · 线路详情**：搜索、排序、逐条预览与应用；线路内部评分只在这里出现，不回到主界面。

---

### 5.2 速度口径（只作相对比较）

主指标是「页面打开耗时（页面基本加载完，不执行页面脚本）」，只在「检查与修复 → 官网诊断 → 防护版预览」里出现，并且必须并排展示当前直连与备选 IP 两组数据。

- 口径：同一次测量中交替对比，比较当前直连与备选 IP 的页面打开耗时，不执行页面脚本；
- 用途：只用于相对比较，不是绝对真值；
- 禁止：不能单独用这一个数字下“变快了”的结论；
- 其他毫秒数（单次请求、平均响应、加密连接握手、下载吞吐）均已在原位置标注口径。

---

### 5.3 自动测速与线路管理

自动测速只影响界面显示，不会改 Hosts。

| 能力 | 说明 |
|------|------|
| 自动测速 | 启动后在后台定时采样各加速线路的单次响应（间隔在设置页调整）；只影响界面显示，不提供首屏暂停入口 |
| 线路详情 | 主界面折叠区「📡 我的加速 · 线路详情」：搜索、排序、逐条「仅用此线路」 |
| 自动切换 | 设置页「自动切换最快线路」默认关闭；开启后由程序按同一套 20% 口径自动换线路 |
| 自动应用 Hosts | 设置页「自动应用 Hosts」默认关闭；开启后才会在启动/切换时直接写入 |

线路内部评分只在线路详情里可见，不作为主界面结论依据。

### 5.4 检查与修复（含连续采样）

左侧「检查与修复」把原来的「依赖站点检查」「官网访问诊断」「网络监控」合并为一页：

- **结论**：先给“哪里有问题”的判断；
- **明细**：依赖站点单次请求耗时、官网诊断（解析层是否瓶颈）；
- **连续采样**：原网络监控曲线，默认折叠、按需展开。

所有动作只读，不改 Hosts / DNS / 代理。

#### 5.3.1 监控服务

| 服务 | 说明 |
|------|------|
| github.com | GitHub 主站 |
| api.github.com | GitHub API |
| assets-cdn.github.com | 静态资源 CDN |
| codeload.github.com | 代码下载服务 |

#### 5.3.2 延迟曲线

实时绘制延迟变化曲线，帮助发现网络问题。

## 6. 设置配置

```
%AppData%\GithubAccelerator\
├── config.json          # 应用配置
```

`config.json` 示例：

```json
{
  "version": "1.1.0",

  "autoMonitor": true,
  "refreshInterval": 300,
```

如需重置所有配置：

1. 关闭应用程序
2. 删除 `%AppData%\GithubAccelerator\config.json`
3. 重新启动应用程序

## 7. 常见问题

### Q1: 应用后仍然无法访问 GitHub？

**解决方案**:
1. 检查是否以管理员身份运行
2. 清除 DNS 缓存：打开 CMD，执行 `ipconfig /flushdns`
3. 尝试刷新数据源后重新应用
4. 检查是否有其他代理软件冲突

### Q2: 提示"需要管理员权限"？

**解决方案**:
1. 先区分两种提示：若提示「当前网络换 IP 改善不了」是**准入未通过**（预期行为，不会请求提权、不修改 Hosts）；若提示"需要管理员权限"才是提权环节
2. 判定通过后按 UAC 提示授权即可；也可以右键点击应用图标，选择"以管理员身份运行"
3. 或在属性中设置"以管理员身份运行此程序"

### Q3: 数据源全部超时？

**解决方案**:
1. 检查网络连接是否正常
2. 检查防火墙是否阻止应用
3. 等待一段时间后重试
4. 尝试使用代理

### Q4: 应用后访问变慢了？

**解决方案**:
1. 点击刷新按钮重新测速
2. 选择响应时间更短的数据源
3. 清除 Hosts 后重新应用

### Q5: 如何完全卸载？

**解决方案**:
1. 先点「停止加速」（或执行 `GithubAccelerator.Cli.exe --restore`），确认 Hosts 里的加速块已移除
2. 通过系统设置卸载应用
3. 手动删除 `%AppData%\GithubAccelerator` 文件夹
4. 检查并清理注册表自启动项

### Q6: 开机自启不生效？

**解决方案**:
1. 检查设置中是否勾选了"开机自启"
2. 检查是否被安全软件拦截
3. 手动添加到启动文件夹
