# 官网访问加速设计（Hosts 优选 IP）

文档状态：M1 已完成（只读诊断面板，不写 Hosts）；M2 不做（用户已拍板）
编写时间：2026-11-06（Asia/Shanghai）
适用产品：GithubAccelerator（自用版，无任何上游出口）

---

## 0. 核心判断（先看这一节）

**现状**：当前产品实际是"下载加速器"。官网（github.com 页面浏览、issue/PR、搜索、登录入口）只能靠"镜像版页面"凑合，而 2026-11-06 13:50 实测 ghfast.top 页面路径返回 **HTTP 403 / 14 字节**，99988866 TLS 握手失败，GHProxy 5s 超时——镜像版页面**不能**替代官网浏览（详见 `docs/Optimization_Plan_20261105.md` §十、§十一）。

**本设计定位**：用 **Hosts 优选 IP** 改善"解析层"的官网访问，不引入出口、不装证书、不做 MITM/PAC/内置代理、不改系统 DNS 设置。

**能力边界（必须先讲清）**：

| 类型 | 能否解决 | 说明 |
|---|---|---|
| DNS 解析被污染（解析到错误/不可达 IP） | 能 | Hosts 覆盖系统解析结果，优先级高于 DNS |
| 解析到慢节点 / 解析耗时高 | 能（有限） | 只能选一个 IP，无法按连接动态择优 |
| IP 层阻断、丢包、QoS 限速 | **不能** | 瓶颈在传输层，改解析无效 |
| 需要鉴权且必须连 GitHub 服务器的操作（登录、提交、PR、push） | **不能保证** | 仍依赖到 GitHub 的真实连通性；本方案不改变这一点 |
| github.githubassets.com 等 CDN 静态资源的最优边缘选择 | **可能变差** | 固定单个 IP 会绕过 CDN 调度，见 §8 |

**直连可用时不应强行启用**：2026-11-06 13:31 实测直连 `https://github.com/jingshui127/GithubAccelerator` **200 / 1.56s**（含仓库名特征校验）；而 2026-11-05 21:45 同一路径 **12s 超时**。同一台机器、同一网络，两天结论相反，说明这是**时变**问题，任何"直连不可用"的表述都必须带实测时间。产品默认行为应是：**先测直连，直连可用就不写 Hosts**。

## 2. IP 候选来源

### 2.1 DoH 端点（只读查询，2026-11-06 13:53 实测）

| 端点 | 结果 | 耗时 | 结论 |
|---|---|---|---|
| `https://dns.alidns.com/resolve?name=github.com&type=A` | 200，返回 `20.205.243.166`（TTL 53s） | 0.49s | 可用，作为主候选源 |
| `https://doh.pub/dns-query?name=github.com&type=A`（Accept: application/dns-json） | 200，返回 `140.82.114.4`（TTL 11s） | 0.31s | 可用，作为第二候选源 |
| `https://dns.google/resolve?name=github.com&type=A` | 无响应（curl 000，6s 超时） | 6.0s | 本机不可达，不列入 |

系统 DNS 同日解析结果：`20.205.243.166`（与阿里 DoH 一致，说明**当前未被污染**）。

候选集 = 各 DoH 返回的全部 A 记录（去重），再叠加"当前系统解析结果"作为对照组；不做无来源的 IP 猜测。

### 2.2 第三方公开 hosts 项目数据

**默认不采信**，作为决策点 5 单独列出。风险：数据来源不可审计、可能被投毒（指向攻击者 IP 或失效 IP）、更新不可复现。若要引入，必须满足：明确来源仓库、可校验的提交记录、只取域名→IP 对且不执行其中任何脚本、与 DoH 结果交叉验证不一致则丢弃。

### 2.3 不做 SSH / 443 备用端口候选

`ssh.github.com:443` 属于 git 传输通道，与"官网页面浏览"无关；本设计不纳入，避免扩大范围。

## 3. 测速方法

对每个候选 IP、每个目标域名做**应用层近似**探测，而不是只 ping（ping 只反映 ICMP，常被限速或禁用，且不代表 TLS 路径）：

1. `TcpClient.ConnectAsync(ip, 443)`，超时 5s；
2. 成功后在同一个 socket 上 `SslStream.AuthenticateAsClient(域名)`（**必须带正确 SNI**，否则 GitHub 边缘可能直接断开或返回错误证书）；
3. 记录 **TCP 建连耗时 + TLS 握手耗时**，取两者之和为该 IP 的"握手耗时"；
4. 每个 IP 采样 **3 次**，取**中位数**（避免一次冷启动/抖动决定结果）；
5. 并发上限 **4**（避免把本机带宽或对端限流打满，导致排序失真）；
6. 失败判定：TCP 超时、TLS 失败、证书域名不匹配、握手 > 2s，均记为失败；**不允许把失败按 9999ms 混进排序**，应单独计数，且失败样本不参与中位数。

### 3.1 如何避免把 CDN 边缘节点选成"最慢的那个"

- `github.githubassets.com`、`avatars.githubusercontent.com` 走 CDN，不同 IP 代表不同边缘；固定一个 IP 会让部分资源绕远。
- 对策：**分批测量、按域名独立维护**，不共用一张全局 IP 表；CDN 类域名只在"该域名解析结果本身不可用"时才写入，且优先使用该域名自己的 DoH 结果，而不是 github.com 的 IP。
- 判定阈值按域名分别设置（§4.2），避免用一个阈值把 CDN 的 100ms 差异误判为"必须优选"。

### 3.2 2026-11-06 13:54 一次性只读探测（示例，非完整测量）

| IP | 来源 | TCP+TLS（单次） | 结果 |
|---|---|---|---|
| `20.205.243.166` | 阿里 DoH / 系统 DNS | 419ms | OK，TLS 1.3 |
| `140.82.114.4` | 腾讯 DoH | 538ms | OK，TLS 1.3 |
| `140.82.113.4` | 公开 GitHub IP 段（补充候选） | 582ms | OK，TLS 1.3 |
| `140.82.112.3` | 公开 GitHub IP 段（补充候选） | 535ms | OK，TLS 1.3 |

说明：这是单次、单域名（github.com）、未取中位数的冒烟结果，只用于验证"探测方法可行"，**不能**作为优选结论。正式实现必须按 §3 的 3 次采样 + 中位数。

## 4. 选择与准入

### 4.1 选择规则

1. 候选 IP 按 §3 的握手耗时升序排序；
2. 取**最快 N 条**：`github.com` 取 2 条（1 主 1 备，写 Hosts 时由用户选择或按顺序尝试），其余域名各取 1 条；
3. 同分（差值 ≤ 30ms）时优先"系统 DNS 当前返回的 IP"（减少无谓变更）。

### 4.2 健康阈值（建议，需决策点 3 拍板）

| 域名类别 | 准入阈值 | 说明 |
|---|---|---|
| `github.com` | 握手 < 800ms | 2026-11-06 实测 419–582ms，留余量 |
| `api.github.com` | 握手 < 900ms | 与主站同池，略放宽 |
| CDN 类 | 握手 < 500ms 且优于系统解析结果的 30% 以上 | 收益不足则不写 |

### 4.3 全部不合格时的行为

- **不写入任何 Hosts 内容**，不写"一部分"；
- 界面给出：检测时间、每个 IP 的失败原因（超时 / TLS 失败 / 超阈值）、以及一句"本次未做改动，Hosts 保持原样"；
- 保留既有"直接访问 github.com"的原始链接，不自动打开浏览器。

## 5. 写入与回滚

复用现有 [HostsFileManager](file:///E:/CsharpCode/repos/GithubAccelerator/GithubAccelerator.Core/Services/HostsFileManager.cs)，不新建写入通道：

| 能力 | 现有实现 | 本方案如何用 |
|---|---|---|
| 标记块 | `StartMarker` / `EndMarker`（`# === GitHub Accelerator ... ===`） | 只写块内，绝不覆盖块外用户内容 |
| 原子替换 | `ApplyBlockAsync` → `WriteAtomicAsync`（失败则原文件不变） | 整块一次性写入；任一步失败即整体回退 |
| 首启快照 | `WindowsHostsFileService.BackupHostsFileAsync()`（`hosts.backup`）+ `ReplaceAllAsync` 恢复 | 首次写入前快照；"恢复快照"走既有入口 |
| 块级删除 | `RemoveBlockAsync()`（只删标记块，块外顺序不变） | 关闭加速只删块 |
| 被手动修改提示 | `HostsBlockStateStore` 记录 `BlockSha256`，`IsBlockModified` 比对 | 用户改过块内内容时提示"检测到手动修改"，不静默覆盖 |
| 变更记录 | `HostsBlockState` | 扩展记录"前值→后值 IP 列表"（本次新增字段，不影响旧状态读取） |

**每次变更必须记录**：时间、域名 → 旧 IP（或"原无记录"）→ 新 IP、来源 DoH 端点、握手中位数。写入前先备份当前 hosts 内容到状态文件，供"撤销本次"使用。

**绝不**：删改块外行、改系统 DNS 设置、写代理配置、注册开机常驻服务。

## 6. 刷新策略

- **触发条件**：仅启动时检查；缓存有效期 **24 小时**（IP 漂移常见，TTL 实测只有 11–53s，但每次启动都全量测速代价过高）。超期后**仅提示**"可重新优选"，不静默写入。
- **手动刷新**：加速页提供"重新测速"按钮，进度条显示"已完成 X / 共 N 个候选 IP"（沿用现有长任务进度模式）。
- **全失败降级**：不写入、保留现有 Hosts 块不动、给出原因与检测时间；下一次启动重试。
- **不做后台常驻轮询**：不做定时任务、不做托盘后台测速。

## 7. 与镜像策略的关系

两者语义不同，可以并存，但优先级必须写死：

| 场景 | 第一优先 | 后备 | 理由 |
|---|---|---|---|
| 官网页面浏览（github.com 仓库页/issue/搜索） | **直连 + Hosts 优选** | 镜像版页面（仅当页面路径健康检查通过） | 镜像页不是 github.com 本身（登录/交互不可用） |
| git clone/fetch/pull | 镜像 `insteadOf`（默认 gitclone.com，2026-11-06 实测 0.49s） | 直连 | URL 在 DNS 之前就被改写，Hosts 对镜像地址无效 |
| git push | **直连 github.com** | 无 | 镜像不做鉴权转发，push 无法加速（已验证） |
| release / raw 下载 | 镜像前缀 | 直连 / Hosts | 现有能力已覆盖 |

冲突处理：Hosts 条目只影响解析，不改变 `insteadOf` 的改写结果；若镜像域名与 Hosts 域名重叠（不会出现），以镜像改写后的域名为准。

## 8. 风险与副作用

| 风险 | 影响 | 应对 / 不做的理由 |
|---|---|---|
| IP 漂移 | Hosts 条目 1–3 天后失效，表现为超时 | 24h 缓存 + 启动提示重测；不做长期固化；失败时一键"清除加速块" |
| 安全软件拦截写 Hosts | 写入失败或写入后被还原 | 复用现有失败提示与原子写；不尝试绕过、不提权安装驱动、不加白名单 |
| CDN 边缘非最优 | `githubassets/avatars` 变慢，首屏反而更慢 | 默认不写 CDN 域名；仅在优于系统解析 30% 时才写（§4.2） |
| 多网卡 / VPN / 代理 | Hosts 对 VPN 内流量同样生效，可能指向不可达 IP | 检测到活动 VPN/系统代理时**默认不启用**，并提示原因 |
| IPv6 | 只写 IPv4 时，系统可能仍优先走 IPv6 而绕过 Hosts | 第一版**只处理 IPv4**；若系统解析存在 AAAA 且可用，则不改写并说明"当前走 IPv6" |
| 单 IP 无冗余 | 该 IP 故障即全站不可用 | `github.com` 允许写 2 条（同域名多行，系统按顺序尝试）；失败可一键清除 |
| 管理员权限 | 写 `hosts` 需要管理员，普通权限直接失败 | 明确提示"需要以管理员身份运行"，不静默降级、不假装成功 |

## 9. 明确不做

- 不做本地代理 / PAC / 系统代理设置；
- 不做 MITM、不装证书、不解密流量；
- 不改系统 DNS 设置（不写注册表、不调 `netsh`）；
- 不做后台常驻测速/轮询；
- 不自动打开浏览器、不自动跳转镜像页；
- 不采信第三方 hosts 数据（除非决策点 5 明确批准）；
- 不承诺"登录/PR/push 一定能通"；
- 不把"写入成功"表述为"已加速"——只表述为"已写入 N 条解析记录，实测耗时见下表"。

## 10. 测试计划

### 10.1 单元测试

| 用例 | 断言 |
|---|---|
| DoH JSON 解析 | 仅取 A 记录、去重、忽略 CNAME 目标为其他域名 |
| 排序与中位数 | 3 次采样取中位数；失败样本不计入；并发上限生效 |
| 阈值准入 | 低于/等于/高于阈值的边界；全不合格时返回空结果 |
| 原子写与回滚 | 模拟写入失败 → 原文件字节不变；块外内容与行序不变 |
| 半失败 | 3 个域名中 1 个测速失败 → 不写入任何内容（全有或全无） |
| 手动修改检测 | 块内被改后 `IsBlockModified` 为真，界面给出提示 |
| 撤销 | 记录的前值恢复后，hosts 与写入前 SHA256 一致 |

### 10.2 实机测试

1. 记录写入前 `hosts` SHA256 与页面耗时（`curl -w "%{time_total}"`，3 次取中位数）；
2. 写入后重复同样测量，记录域名级耗时对比；
3. 执行"清除加速块"，再次校验 hosts SHA256 与写入前一致；
4. 用非管理员权限复跑写入，确认给出明确失败提示且文件未变。

### 10.3 失败路径

DoH 全不可达、候选 IP 全部超时、TLS SNI 不匹配、写入中途失败、写入后用户手动改块、VPN 在线。每种都要有"不写一半、原因可读"的表现。

## 12. 待用户拍板的决策点

1. **是否默认开启？** 建议：**默认关闭**。依据：2026-11-06 13:31 直连 200/1.56s，属"可用"，强行启用可能引入负收益；只在用户点"测一下"后给出建议，再由用户手动写入。
2. **刷新间隔？** 建议：**24 小时**（启动时检查 + 手动刷新），不做后台轮询。DoH TTL 只有 11–53s，频繁刷新没有意义且增加写 Hosts 次数。
3. **准入阈值？** 建议：`github.com` 握手中位数 < 800ms；CDN 类"优于系统解析 30% 且 < 500ms"；全不合格不写。
4. **是否同时写 `api.github.com`？** 建议：**写**，但只在它自己测速合格时写；未登录页面大量依赖它，缺了它首屏数据会失败。
5. **是否采信第三方公开 hosts 项目？** 建议：**不采信**（投毒/不可审计/不可复现）。若必须引入，只做交叉验证后的补充，不替代 DoH。
6. **是否写 CDN 域名（githubassets/avatars/camo）？** 建议：**默认不写**，只有"系统解析不可用或明显更差"时才写，避免固定 IP 破坏 CDN 调度。
7. **IPv6 怎么处理？** 建议：第一版只写 IPv4；检测到 AAAA 记录可用时提示"当前走 IPv6，未改写"。
8. **写两条 `github.com` 记录做冗余？** 建议：**允许 2 条**（主备），代价是同域名多行在部分系统上只取第一条，需在界面说明"第一条生效"。

### 13.1 M1 实机记录（产品自身，只读）

- **面板位置**：主界面左侧「主要功能 → 官网访问诊断」，截图见 `docs/screenshots/official-site-diagnostics-20261106-1431.png`。
- **范围**：`github.com`、`api.github.com`、`codeload.github.com`、`raw.githubusercontent.com`；DoH 只用阿里 / 腾讯。`gist.github.com` 按 §1.3 归为可选、默认不写，M1 未纳入（多测不改变“解析层是否瓶颈”的判断）。
- **阈值与参数**：单次 5s、并发上限 4、每 IP 采样 3 次取中位数（多数成功才算可用）；候选比基线快/慢 20% 以上才分类为“更快/更慢”。
- **四次连续实机结论（同一台机器、同一网络，间隔数分钟）**：
  - 14:24:21 / 14:29:40：所有候选与基线相同或更慢 → “瓶颈不在解析层，Hosts 加速预计无收益”。
  - 14:27:17：github/api/codeload 候选=基线；raw 基线 IP 超时、候选可用（最快 341ms）→ 结论仍为“预计无收益”，另附补充观察。
  - 14:31:12：仅 raw 的候选 324ms 比基线 414ms 快 22% → “有优化空间”，但 github/api/codeload 仍无差异。
- **结论（2026-11-06 14:31:12 实测）**：主域解析层非瓶颈，候选与基线握手时间相同（209=209 / 202=202 / 204≈204）；`raw.githubusercontent.com` 的 22% 差异为 CDN 边缘时变，数分钟内翻转，不作为决策依据；**M2 不做**。
- **解读**：对官网主域（github.com / api / codeload），本机当前网络下**解析层不是瓶颈**；raw 这类 CDN 边缘域名存在数分钟内翻转的差异，Hosts 优选收益不稳定。该结论只用于判断是否值得进入 M2，不构成“启用 Hosts 一定能加速”的承诺。
- **未验证**：`objects.githubusercontent.com`（无签名 URL）、第三方 hosts 项目数据（未采信）、IPv6 场景（M1 只测 IPv4）。
